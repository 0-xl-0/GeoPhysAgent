## 1. 文档目的

本文定义 GeoPhysAgent 第一版可交付产品的用户、范围、行为、验收标准和非目标。它是 v0.1 产品设计、技术实现、测试和发布验收的共同依据。

GeoPhysAgent 的长期定位是：

> 一个由 LLM 驱动、以本地和外部专业 Tool 执行任务、由 Harness 对计划、证据、验证和产物进行约束的地球物理 Agent。

v0.1 不试图覆盖全部地球物理领域，而是通过一个完成度足够高的 LAS 测井数据质控与基础分析工作流，验证以下核心命题：

1. Agent 能把自然语言任务转换为受约束的专业执行计划。
2. 专业工具能以稳定、结构化、可追溯的方式执行。
3. Validator 能发现数据、过程和结果问题，并真正影响任务流转。
4. 系统能交付不仅包含结论，还包含计算结果、验证证据和运行履历的分析包。
5. 新工具和新验证规则能够通过公开契约接入，而不修改自研 Agent Runtime。
6. Geo Tool Registry 能以统一领域契约承载不同实现来源，并由 Bundled LAS MCP Server 证明 MCP 是可用的外部集成路径之一。
7. 用户能通过环境变量配置第三方 API Key 和模型，并由可替换 Model Provider 驱动 Agent Loop。

## 2. 第一版定义

### 2.1 产品名称

GeoPhysAgent v0.1 — LAS QC Reference Workflow

### 2.2 第一版一句话描述

用户提供一个 LAS 文件并用自然语言描述任务，LLM Agent 必须参与意图理解、计划、Tool 选择和结果解释；专业计算在受控 Tool 中执行，Harness 验证结果并生成可审计的 Markdown 报告、图件和结构化结果；随项目发布的 LAS MCP Server 同时展示外部能力的标准接入方式。

### 2.3 主要用户

#### 地球物理专业用户

- 测井解释人员
- 地球物理工程师
- 地学研究人员
- 需要快速检查 LAS 数据的数据工程师

他们主要关心任务是否完成、数据问题是否被发现、结果是否可信以及成果能否直接查看和交付。

#### 扩展开发者

- 地球物理算法工程师
- Agent 应用开发者
- 希望接入自研算法的研究团队

他们主要关心能否通过稳定领域契约增加 Tool、Validator 和 Skill，并按需要选择内置 Tool Provider 或 MCP Server。v0.1 不提供完整插件市场，但必须提供一个独立示例 MCP Server。

## 3. 核心用户场景

### 3.1 标准场景

用户执行类似任务：

```text
检查 well-01.las 的数据质量，分析主要测井曲线，
绘制标准测井图，并生成一份分析报告。
```

系统应完成：

```text
接收自然语言任务与输入文件
→ 本地建立 DataAsset，不把大型原始数据直接发送给模型
→ 创建 TaskRun 和 AgentRun
→ LLM 理解目标、查询能力并形成候选结构化执行计划
→ Harness 审批计划、Tool allowlist、权限和预期 Evidence
→ 按 Tool Provider 路由并执行本地或 MCP Geo Tools
→ 读取并识别 LAS 元信息
→ 检查深度轴、采样、空值、曲线和单位
→ 执行统计、异常检测和绘图
→ 验证计算结果及图件
→ LLM 依据已验证 Evidence 生成最终解释
→ Harness 验证最终回答并生成报告和证据包
```

Bundled LAS MCP Server 可以承担这条参考工作流中的一组专业 Tool，但用户体验和领域流程不得依赖用户理解 MCP。即使未来替换为内置实现或其他 Provider，Task、Skill、Validator 和分析包语义也保持不变。

### 3.2 信息不足场景

当用户要求系统做超出数据支持范围的解释，例如“判断所有储层位置”，系统应：

1. 识别任务中可执行和不可可靠执行的部分；
2. 继续完成数据质控和客观统计；
3. 明确列出缺少的井区、地层、岩性、解释模型或标定信息；
4. 不把未经支持的推断写成确定结论；
5. 必要时请求用户补充数据或确认假设。

### 3.3 异常数据场景

当 LAS 文件存在深度倒序、重复深度、大量空值、未知单位或损坏头信息时，系统应：

- 给出结构化问题清单和严重程度；
- 区分可自动处理、需用户确认和不可继续的问题；
- 保留原始文件，不原地修改；
- 只在规则允许时创建规范化后的派生数据；
- 在结果不可信时停止，而不是生成伪装成功的报告。

### 3.4 中断恢复场景

任务在模型调用、工具调用或报告生成期间中断后，系统应从已持久化的安全边界恢复。已经完成且不可安全重放的外部效果不得被静默重复执行。

## 4. 功能范围

### 4.1 输入

v0.1 支持：

- 单个 LAS 2.0 文件；
- 本地文件路径；
- UTF-8 或可识别的常见文本编码；
- 自然语言任务描述；
- 可选的输出目录、曲线选择和质控配置。

系统必须为输入文件记录：

- 规范化绝对路径；
- 文件大小；
- SHA-256 哈希；
- 检测到的格式和编码；
- 接收时间；
- 原始文件与派生文件关系。

### 4.2 LAS 识别

系统至少应提取：

- LAS 版本；
- 井名及可获得的井元信息；
- 起始深度、结束深度、步长和 NULL 值定义；
- 曲线助记符、单位、描述和顺序；
- 曲线样本数；
- 深度曲线候选；
- 常见曲线类别候选，包括 GR、DT、RHOB、NPHI 和电阻率曲线。

曲线识别必须输出置信度或歧义说明，不能仅返回一个无解释的映射。

### 4.3 数据质量检查

系统至少应检查：

- 文件是否可解析；
- 深度曲线是否存在；
- 深度是否单调；
- 是否存在重复深度；
- 名义步长与实际采样间隔是否一致；
- 曲线长度是否一致；
- NULL 值是否正确识别；
- 每条曲线的有效样本数和缺失率；
- NaN、无穷值及非数值内容；
- 明显异常的数值范围；
- 单位缺失、单位与曲线类型冲突；
- 同名或别名冲突曲线。

每个检查项必须包含检查名称、状态、严重程度、证据、影响和建议动作。

### 4.4 基础分析

对有效曲线至少计算：

- 样本总数和有效样本数；
- 最小值、最大值、均值和标准差；
- P01、P05、P25、P50、P75、P95、P99；
- 缺失比例；
- 可配置规则识别出的异常样本数及对应深度区间。

所有统计必须明确 NULL/NaN 处理方式。报告中的数值必须来自结构化结果，禁止由模型重新估算。

### 4.5 可视化

系统至少生成一张标准测井曲线图：

- 深度向下增加；
- 轨道标明曲线名称和单位；
- 缺失区间可识别；
- 图件记录输入曲线、绘图参数、尺寸和生成工具版本；
- 输出 PNG；
- 图件通过基础完整性检查后才能进入最终报告。

### 4.6 结构化计划

Agent 生成的计划必须被约束为已注册的工作流步骤，不接受自由文本作为唯一执行依据。计划至少包括：

- 任务目标；
- 输入资产；
- 要执行的步骤；
- 每一步使用的 Tool；
- 前置条件；
- 预期产物；
- 验证要求；
- 失败后的允许动作；
- 需要披露的假设。

### 4.7 验证与恢复

Validator 返回 `pass`、`warning` 或 `fail`，并提供是否允许继续的独立决策字段。系统至少支持：

- 对可重试的瞬时工具错误进行有限次数重试；
- 对参数问题使用规则允许的候选参数重新执行；
- 对数据不满足要求的情况停止并说明；
- 对具有实质影响的歧义请求用户确认；
- 记录每次尝试，禁止覆盖失败记录；
- 设置总尝试次数和单步骤尝试次数上限。

### 4.8 报告

最终 Markdown 报告至少包含：

1. 任务摘要；
2. 输入文件和井信息；
3. 曲线清单；
4. 数据质量结论；
5. 曲线统计；
6. 异常及对应证据；
7. 图件；
8. 处理步骤和参数；
9. 假设与限制；
10. 验证状态；
11. 建议的后续工作；
12. 分析包和结构化结果位置。

报告必须区分：

- 数据直接支持的事实；
- 规则产生的判断；
- 模型生成的解释；
- 尚未验证的假设。

### 4.9 LLM-first 命令行参考产品

v0.1 的正式用户主入口至少提供：

```text
geophysagent run <las-file> --task "..." --output <directory>
geophysagent resume <task-id>
geophysagent status <task-id>
geophysagent validate <run-directory>
```

`run` 必须调用已配置的 Model Provider。模型不可用时任务明确失败或等待，不得静默退化为绕过 Agent 的固定工作流。

开发、测试、批处理和诊断接口可以提供：

```text
geophysagent inspect <asset>
geophysagent analyze <las-file> --output <directory>
geophysagent preprocess <asset> --pipeline <file> --output <directory>
geophysagent segy <segy-file> --output <directory>
geophysagent mcp list
geophysagent mcp doctor <server-id>
```

直接确定性命令仍通过同一个 Application/Harness，用于验证专业计算和自动化，不作为最终用户需要理解的产品模式。命令行应显示当前阶段、模型、关键工具调用、警告、等待用户操作状态和最终产物位置。默认输出适合人阅读，同时提供 JSON 输出选项供自动化使用。

## 5. 核心领域对象

v0.1 必须定义并版本化以下对象：

- `TaskSpec`：任务目标、输入、输出和约束；
- `DataAsset`：输入和派生数据资产；
- `ExecutionPlan`：受约束的执行计划；
- `ToolInvocation`：工具、参数、权限和幂等信息；
- `ToolResult`：数据、产物、指标、警告和来源；
- `ValidationReport`：检查项、状态、证据和继续策略；
- `ArtifactManifest`：任务产生的所有文件；
- `RunRecord`：状态、事件、尝试、模型和工具版本。
- `ModelProfile`：Provider、模型、协议、Base URL、凭据引用和超时，不包含明文 API Key；
- `McpServerConfig`：Server 身份、传输、信任和超时；
- `IntegrationManifest`：MCP Tool 到 GeoTool、权限和 Validator 的映射；
- `McpConnectionSnapshot`：协商协议版本、Server 能力和连接状态。

对象必须包含 `schema_version`。破坏性变更必须通过显式迁移或拒绝读取来处理，不能静默误读旧数据。

## 6. 非功能要求

### 6.1 可追溯性

- 报告中的每个关键数字可追溯到具体 ToolResult；
- 每个产物可追溯到输入资产、工具、参数和版本；
- 每次任务保存完整状态转移和验证记录；
- 输入文件使用内容哈希标识。
- 每个专业 ToolResult 可追溯到 Tool Provider、工具版本和 Tool Schema 快照；来自 MCP 的结果还要记录 Server 与协议版本。

### 6.2 可复现性

- 相同输入、配置和工具版本应产生一致的确定性计算结果；
- 模型生成文字允许变化，但不得改变已验证的事实；
- 报告必须记录模型标识、工具版本、规则集版本和运行时间。

### 6.3 安全性

- 默认本地处理数据；
- 默认禁止网络工具；
- 输入文件内容一律作为不可信数据，不能成为 Agent 指令；
- Tool 只能访问任务明确授权的路径；
- MCP Server、Tools、Resources、Prompts 和 instructions 均视为不可信外部输入；
- Server Tool 必须经过本地 allowlist 和 Integration Manifest 才能对 Agent 可见；
- 不原地修改输入文件；
- 密钥不得进入报告、事件日志或模型上下文；
- 模型 API Key 只从环境变量或受控本机凭据存储读取，项目配置只保存引用；
- Model Provider 不可用时不得静默切换到另一个供应商或模型；
- 发送给远程模型的数据范围必须可配置且可记录。

### 6.4 可靠性

- 工具超时、进程崩溃和无效返回值必须被捕获；
- MCP 连接或能力协商失败、协议不兼容、Server 断线和非法 ToolResult 必须被捕获；
- 已持久化的任务可以恢复或明确进入不可恢复状态；
- 最终状态只能是 `completed`、`completed_with_warnings`、`failed` 或 `cancelled`；
- `failed` 不得生成表面上表示成功的最终报告。

### 6.5 性能基线

首版不设置激进性能目标，但应记录并在发布前固定基准：

- 启动耗时；
- LAS 解析耗时；
- 每条曲线统计耗时；
- 绘图耗时；
- 峰值内存；
- 模型调用次数和 Token 使用量。

发布基准使用小、中、大三个固定测试文件，性能退化必须可检测。

## 7. 第一版非目标

以下内容明确不属于 v0.1：

- SEGY、SEG-D、DLIS、栅格和矢量数据；
- 多井相关、地层对比和区域解释；
- 自动储层评价或岩性定论；
- 地震属性和断层解释；
- 反演和地球物理建模；
- 任意、无约束的代码执行作为标准工作流；受控 Explore 仅用于长尾表格任务，结果必须标记为探索级并保留代码与运行记录；
- Multi-Agent；
- 跨项目长期 Memory；
- 完整桌面端或 Web 管理平台；
- 多租户、企业身份和远程任务调度；
- 对所有 LAS 厂商扩展的完整兼容；
- 将 GeoPhysAgent 自身作为通用 MCP Server 对外发布；
- 自动信任和启用任意第三方 MCP Server；
- 通过 MCP 消息传输完整大型地球物理数据；
- 正式支持远程 Streamable HTTP MCP Server；v0.1 只承诺本地 stdio Server。

## 8. 验收场景

### A. 正常 LAS 文件

- 成功识别井和主要曲线；
- 生成统计 JSON、质控报告、PNG 图件和 Markdown 报告；
- 所有报告数字能在结构化结果中找到来源；
- 任务状态为 `completed` 或有合理警告的 `completed_with_warnings`。

### B. 深度倒序

- 正确识别深度方向；
- 不把合法的倒序存储误判为数据损坏；
- 绘图仍保持深度向下增加；
- 原始数据顺序和绘图转换都被记录。

### C. 重复深度与不规则采样

- 给出重复位置和异常间隔证据；
- 不静默删除样本；
- 分析继续或停止符合规则配置。

### D. 未知单位

- 标记单位歧义；
- 不执行未经确认的单位换算；
- 报告披露受影响的检查和结论。

### E. 损坏文件

- 任务以明确错误结束；
- 保留失败日志和可操作的错误说明；
- 不生成误导性的成功报告。

### F. 工具进程中断

- 超时或进程退出被识别；
- 安全操作按照上限重试；
- 不安全操作不被静默重放；
- 任务可恢复或明确失败。

### G. 超范围请求

- 系统完成可可靠执行的质控部分；
- 拒绝无依据的确定性地质结论；
- 报告明确所缺数据和建议下一步。

### H. MCP Server 不可用

- 启动失败、能力协商失败、协议不兼容和异常退出被明确区分；
- 不生成伪成功报告；
- 已完成且安全的步骤保持可恢复；
- 诊断信息不泄露凭据。

### I. 第三方示例 MCP Server

- GeoPhysAgent 能完成连接、版本与能力协商；
- 只注册本地 allowlist 中的 Tool；
- MCP structuredContent 被映射并通过 GeoTool Schema；
- Server instructions、Resources 和 Prompts 不会自动成为系统指令。

### J. 真实 MiniMax Agent

- 通过显式在线测试开关和环境变量 API Key 启动，不从配置、日志或 Artifact 读取明文密钥；
- LLM 完成意图理解、Tool Call、结果回填和最终回答，而不是由测试代码预先固定完整执行路径；
- 最终回答引用本次 TaskRun 中真实产生的 Evidence；
- 测试允许产生 API 费用和措辞差异，只验证结构化轨迹、状态、证据和安全边界；
- 候选发布前至少通过 LAS、表格 Explore 和一个多 Tool 在线场景。

### K. 模型不可用

- 凭据缺失、网络失败、限流和协议错误被明确区分；
- 正式用户任务不得静默绕过 LLM 改走确定性命令；
- 已提交的 Tool Result、Evidence、Artifact 和 Checkpoint 不被破坏；
- 任务进入可诊断的失败或等待状态，并给出重试或切换 Provider 的操作建议。

## 9. 发布成功指标

v0.1 发布前至少满足：

- 黄金数据集中的所有严重问题均被正确检出；
- 正常样本不出现发布阻断级误报；
- 报告事实引用追溯率为 100%；
- 输入文件零原地修改；
- 故障注入用例不会导致伪成功；
- 在干净的受支持环境中可按文档完成安装和示例任务；
- 至少一名非项目开发者能根据文档增加一个 Validator；
- 至少一名非项目开发者能根据文档创建并接入一个最小 MCP Server；
- 至少一名地球物理用户能独立完成标准工作流并理解结果；
- 默认无网测试套件全部通过，且真实 MiniMax LLM-first 端到端验收通过；

## 10. 发布物

v0.1 发布包包括：

- GeoPhysAgent CLI；
- Python Application Service、Agent Runtime 和 GeoDomainHarness；

## 11. 仍需在开发前确认的产品决策

7. v0.1 是开发者预览版、内部试用版还是公开发布版。
